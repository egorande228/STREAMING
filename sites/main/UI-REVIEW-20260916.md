# Schedule and Arabic UI review

Base: `a5c9133` on `codex/kinglive-ui-handoff-20260911`.
Scope: presentation and browser-side loading/cache handling in `sites/main`.
No deployment, infrastructure operations, Worker edits, stream selection,
match identifiers, API configuration, advertising or analytics changes.

## Why an empty schedule flashed before matches appeared

Reproduced with deterministic delayed responses against the real `app.js`:

1. The independent active-stream request can complete before the schedule.
   Its `renderMatches(currentMatches)` call receives the initial empty array
   and used to replace the loading skeleton with `No matches`.
2. A cached match on a different date used to trigger the same empty-day
   render while the selected date was still loading.
3. `Promise.all` rejected the entire three-day request when one adjacent UTC
   date failed, discarding successfully loaded fixtures. The catch path also
   used the empty-day message for a network failure.
4. Browser cache writes accepted `schedule_stale` responses, resetting their
   observation time and making old data appear freshly fetched.

The UI now distinguishes loading, confirmed empty and unavailable schedules.
Successful day responses survive adjacent-day failures; unavailable schedules
offer retry. Existing cached fixtures remain visible while loading. A stale
fallback never renews the browser cache timestamp. Late initial responses cannot
replace a newer day selection. API endpoints, request parameters and server
cache configuration remain unchanged.

## Server cache review — read only

Inspected `workers/football-api/current-production/worker.mjs`,
`upstream-cache.mjs` and `match-registry.mjs`; these snapshot files were not
changed or deployed. Live D1/KV contents and Cloudflare configuration were not
accessed.

The upstream gate can return 503 after five failed lease attempts, and the
schedule registry has a bounded stale-day fallback. The outer public list
cache accepts valid empty arrays, so a 200 response alone does not establish
that every provider succeeded. In particular, registry recovery is gated on
all three official sources being `null`; a partial provider failure alongside
an empty successful source deserves a separate server-side completeness review.
That is a code-review finding, not a reproduced production outage. This UI
patch addresses the independently reproduced frontend races; it does not
claim to repair the server or change source selection.

## Presentation

- Arabic display dictionary: 66 distinct clubs, covering 20 PL, 20 LaLiga and
  36 UCL league-phase participants for 2026/27. Sources: `TEAM-NAMES.md`.
- Scoreboard, cards and lineup headings use the same translations; originals
  remain available for crest lookup and provider identity.
- Dates use the Gregorian calendar, western digits and 24-hour time. `+3`
  has its own left-to-right isolation inside the Arabic timezone label.
- League aliases such as `La Liga` / `2026-27 LALIGA` and `UEFA Champions
  League` / `Champions League` no longer appear twice. Distinct matchdays and
  phases remain; a missing stage no longer invents `World Cup`.
- Long team labels wrap and reduce font size. Card crests: 40px desktop /
  36px mobile; detail crests: 72px / 44px.
- News stays selected during anchor scrolling and at the bottom of short
  pages; manual scrolling resumes section tracking.

## Verification

Run from repository root:

```sh
npm test --prefix sites/main
npm run build --prefix sites/main
node --test ops/automation/*.test.mjs
git diff --check
```

Local browser fixtures cover EN/AR at 320, 390, 768, 1440 and 1920 pixels,
including long names, mobile match details and News navigation. Fixtures use
test matches, not broadcasts. They are not shipped in the build.

Result on 2026-09-16: all 63 main-site tests and 36 automation unit tests passed;
the static build and diff whitespace checks passed. All ten EN/AR viewport
combinations had zero horizontal overflow and no clipped team containers.
News remained active on a short page where its heading could only scroll to
373px from the top, reproducing the original navigation edge case.

Only the reviewed frontend changes should be considered for any later preview
or production deployment, following `HANDOFF-UI-NEWS.md`.
